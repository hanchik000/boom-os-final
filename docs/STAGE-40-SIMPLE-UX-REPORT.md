# Stage 40 — BOOM OS SIMPLE UX

**Мощно внутри. Просто снаружи.**

Цель этапа: сделать существующий интерфейс понятным человеку, который впервые сел за BOOM OS,
не уменьшая функциональность и ничего не переписывая. Этот этап **не менял ни одной бизнес-механики**
— в диффе нет ни одного файла из `server/`, `prisma/` или `tests/*_e2e.mjs`.

---

## 2. Новая структура навигации

```
Главная            → Дашборд
Продажи            → Касса · Сводка дня
Заказы             → Заказы и кухня · Сейчас в зале · Согласования
Меню               → Блюда и цены · Как видит гость · Оформление меню · Фото и видео
Склад              → Остатки на складе · Себестоимость
Персонал           → Сотрудники · Доступы
Клиенты            → Клиенты · Долги клиентов
Маркетинг          → Акции · Карты лояльности · Журнал карт
Отчёты             → Отчёты
─────────────────────────────────────────────
Расширенные настройки (отдельно, внизу)
```

Все **31** прежних назначения по-прежнему доступны — этап перегруппировал навигацию, но ничего не удалил.
Раздел, в котором нет ни одного доступного этому человеку пункта, не показывается вовсе.

## 3. Что перенесено в «Расширенные настройки»

Организация · Франшизы · Филиалы · Роли · Проверка прав доступа · Брендинг · Вид чека ·
Сервисный сбор · Экраны POS · Системные параметры · Журнал действий.

Это **только конфигурация**. Ни одна ежедневная операция (касса, заказы, кухня, меню, склад,
клиенты, отчёты) туда не попала — это закреплено тестом. Сам раздел показывается только тому,
кто держит хотя бы одно конфигурационное право; это оформление, права при этом не выдаются и не
отбираются, сервер авторизует каждый запрос как раньше.

## 4. Найденные и исправленные реальные дефекты UX

1. **Кассиру предлагались «Расширенные настройки».** Кассир держит `branches.view`, и этого
   хватало, чтобы показать ему раздел конфигурации. Теперь раздел появляется только у того, кто
   держит конфигурационное право.
2. **Рабочая оболочка не соблюдала «уменьшить движение».** Гостевое меню соблюдало, ADMIN — нет:
   переходы шли 0.15s. Добавлен существующий класс `boom-reduced-motion-safe` (конвенция проекта
   0.001ms не менялась — проверено: `1e-06s`).
3. **403 на каждой загрузке страницы.** `Header` запрашивал список франшиз у всех ролей и список
   филиалов у официанта. Сервер справедливо отказывал, `catch` это прятал — молчаливая ошибка на
   каждом входе. Теперь запрашивается только то, что человеку положено; пустой селектор области
   не показывается.
4. **Экран «Заказы и кухня» полностью падал у кассира.** Все четыре набора данных грузились одним
   `Promise.all`; у кассира нет `kds.view`, отказ по кухне ронял весь запрос, и кассир не видел
   даже собственных заказов и платежей. Теперь каждый блок грузится отдельно и только тем, кому
   он доступен, а раздел без данных не показывается (вместо ложного нуля).
5. **Два мёртвых выпадающих списка.** Выбор блюда для комплимента (касса) и для подарка на день
   рождения (BOOMCARD) грузился через `api.getMenu()` — это эндпоинт **устройства официанта**
   (`/api/menu/pos`, `X-Waiter-Session`). Из браузера его удовлетворить нельзя, запрос всегда
   получал 401, а список всегда был пуст: комплимент нельзя было отправить в принципе. Оба списка
   читают каталог филиала, доступный этим пользователям; сервер по-прежнему проверяет и оценивает
   выбранное блюдо сам.

## 5. Что НЕ менялось

Order Core, Menu Engine, Inventory Engine, Recipe Engine, Food Cost, финансовая логика,
BOOMCARD / BOOMCOIN / BOOMBACK, CRM, RBAC и набор прав, контракты API, схема PostgreSQL
(в этапе нет ни одной миграции), правила источника истины Menu Builder ↔ Visual Catalog,
изоляция филиалов, аудит. Ни одна новая бизнес-функция не добавлена.
