# BOOM OS Stage 14 — Inventory, Recipes & Stock

## Scope
Adds the inventory vertical to the existing Order Core / Cashier / KDS architecture.

### Stock model
- Inventory items are branch-scoped.
- Quantity is stored as PostgreSQL `DECIMAL(14,4)`; money uses `DECIMAL(14,2)`.
- Low-stock rule: `current_stock <= reorder_point`.
- Manual movements: `WASTE`, `ADJUSTMENT`, `TRANSFER_IN`, `TRANSFER_OUT`, `RETURN`.
- `PURCHASE` is generated by receiving a purchase; `SALE` is generated when a paid order consumes a configured recipe.
- Draft orders never change stock.

### Recipes
Each branch can define one active recipe per menu item. Recipe ingredients reference branch inventory items and a decimal quantity. Sale consumption is calculated from recipe ingredient quantity × ordered quantity ÷ recipe yield.

### Purchases
Purchases start as `DRAFT`. Receiving a purchase atomically increases stock and writes `PURCHASE` stock movements. A received purchase cannot be received twice.

### Sale deduction
Payment completion consumes inventory for configured recipes in the same database transaction as payment/order completion. Inventory rows are locked before checking stock. If required stock is unavailable, payment is rejected with `INSUFFICIENT_STOCK` and the transaction rolls back.

### Audit / isolation
Inventory, recipes, suppliers, purchases and stock movements are branch-isolated server-side and material mutations are audited.
